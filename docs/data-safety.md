# Data safety

Preserve independent backups and verify that they restore before editing valuable research. The project library itself is not a backup. Keep original files outside Bio as well as preserved originals within a project.

Original source bytes, working extraction, interpretations, evidence and review decisions serve different purposes. Structural validity and tutorial completion do not certify scientific correctness. Unknown is a valid result; do not replace uncertainty with a convenient guess. Review repairs, mappings, units, dates and missing-value conventions before applying them.

Desktop data normally resides under `%LOCALAPPDATA%\Biodiversity Data Rescue Workbench\projects-data`. Browser/development modes can use other explicit directories. Working storage is local and unencrypted. Optional encrypted portability does not encrypt every working file. Installing or activating a binary version must not migrate or delete research data implicitly.

Packages can include originals, locations, personal contacts and history. Check contents before sharing. Reproduce public issues with synthetic/minimized data; omit confidential files, tokens, support bundles and personal filesystem paths.

Readers and standards checks have format-specific limits. A successful import does not prove complete faithful reconstruction, and a successful structural check is not a scientific compliance certificate. Consult application Help and review extraction warnings.
